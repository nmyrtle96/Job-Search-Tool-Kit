# My standing rules for Claude

These are tuned starting defaults. Edit any you disagree with;
Claude follows this file over its own judgment.

## Résumés
- One page, same layout as my base résumé. No added lines.
- Tailor every job I give you — never skip one as a "duplicate" (same company can be a different
  requisition). Only an identical job id I already applied to or cut gets raised with me instead.
- Over-level roles (8+ years, Staff / Principal / Director / Head of / VP): note it in one line and
  build anyway. Read the bar, not the title.
- Keywords: no keyword more than 4 times on the page (a word that starts a sentence doesn't count).
  Rank JD keywords by the requirements list top-down, then the preferred list; top terms go most
  visible (headline first, summary, earliest bullets).
- Use the job post's exact phrase only where the sentence still reads naturally — no wedged-in keywords.
- No two bullets in one job section start with the same word; open with active, descriptive PM verbs.
- Apply my experience as far as truth allows: reframe adjacent real work in the post's vocabulary.
  Never invent employers, domains, tools or numbers.
- Report weak evidence honestly — a partial fit gets an honest résumé with a named gap.
- After each batch: show me the score table (Fit / Truth / Reads like a PM / Clarity, each /10,
  plus keyword coverage) and auto-cut anything scoring 5 or below on Fit.

## Applications
- Once résumés are built, fill the applications automatically — get me as far as possible.
- Attach the tailored résumé on every application, every time.
- Never click the final submit. Never type a password or create an account. Never tick consent,
  terms, attestation or marketing boxes without asking. Cookie banners → Reject. SMS consent → No.
- Voluntary self-identification (gender, race, veteran, disability…): always the decline option,
  never blank — including saved answers on aggregator profiles.
- When my real answer isn't clearly on file (no option matches, desired pay with no range posted),
  ask me — don't make the call.
- Free-text answers: write them the way a person would (80–150 words, first person, one or two real
  numbers), never template filler. List every drafted answer so I can read it before submitting.
- "Why you?" answers: combine the résumé with my 30-second pitch, using the résumé's numbers.
- Optional "why are you leaving" questions → leave blank.

## Housekeeping
- When I say a batch was submitted: mark it confirmed and run `archive_sent.py` so sent résumés move
  to Archive/ and finished JD files move to JD Archive/. Every time.
- A closed browser tab is not a submitted application — ask.
- End each working session with a short handoff doc in the Claude Project (see HANDOFF-TEMPLATE).
